# HarnessX build provenance

HarnessX is open source under the MIT License. The provenance system does not prevent copying, modification, or redistribution. It lets developers distinguish an unchanged artifact produced by the official `n4thyan/HarnessX` workflow from an unverified or modified copy.

## What an official artifact contains

The release workflow builds these files:

```text
HarnessXPlugin.lua
HarnessXPlugin.manifest.json
SHA256SUMS
```

`HarnessXPlugin.lua` starts with a metadata banner containing the repository, version, commit, build ID, source SHA-256, build channel, and deterministic build timestamp.

The manifest records:

- the SHA-256 of `roblox/Plugin.lua` used as input;
- the SHA-256 and size of the generated plugin artifact;
- the repository, version, commit, channel, and build timestamp; and
- the command used to verify the GitHub artifact attestation.

The banner is deliberately labelled as metadata rather than proof. Anyone can edit a text banner. Authenticity comes from matching checksums and a valid GitHub attestation associated with this repository.

## Build locally

From the repository root:

```bash
python tools/build_plugin.py \
  --version development \
  --commit "$(git rev-parse HEAD)" \
  --channel local \
  --output-dir dist
```

For reproducible output, supply a fixed commit timestamp:

```bash
python tools/build_plugin.py \
  --version v1.0.0 \
  --commit "$(git rev-parse HEAD)" \
  --channel local \
  --built-at "$(git show -s --format=%cI HEAD)" \
  --output-dir dist
```

Identical source, metadata, and timestamp inputs produce identical artifact, manifest, and checksum files.

## Verify local integrity

Keep the plugin, manifest, and checksum file together, then run:

```bash
python tools/verify_build.py dist/HarnessXPlugin.manifest.json
```

This checks the artifact digest, manifest digest, checksum file, repository identity, and banner metadata. It detects ordinary modifications, stripping, and accidental corruption.

Local checksum verification does not prove who produced the files.

## Verify official origin

For artifacts generated by the GitHub release workflow, use GitHub CLI:

```bash
gh attestation verify HarnessXPlugin.lua -R n4thyan/HarnessX
```

A valid result shows that GitHub received a signed build-provenance attestation from a workflow in `n4thyan/HarnessX` for that exact artifact digest.

A copied or modified plugin will fail unless its bytes still exactly match an attested artifact. A replacement banner or recalculated local checksum cannot create a valid attestation for this repository.

## Release workflow

`.github/workflows/release.yml` runs for version tags matching `v*` and can also be started manually. It:

1. checks out the exact commit;
2. derives a deterministic timestamp from that commit;
3. creates the plugin, manifest, and checksum file;
4. performs local verification;
5. uploads the build as a GitHub Actions artifact; and
6. creates a GitHub artifact attestation for the generated files.

## Trust boundary

An official attestation proves repository and workflow origin for a particular digest. It does not guarantee that a plugin is bug-free, suitable for every project, or unchanged after it has been loaded into Studio.

Copies installed directly from `roblox/Plugin.lua` are development source copies. They remain legitimate HarnessX source, but they are not release artifacts and therefore have no release attestation.
